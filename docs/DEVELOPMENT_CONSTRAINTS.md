# 开发环境约束说明

本文档说明本仓库（OldSend）的**实际开发条件**与**责任边界**。

它的作用是：**让外部能看清"我们做了什么、没条件做什么"**，而不是套用一套"有本地 IDE、有 CI、有真机"的标准模板。

> 不同仓库条件不同。本文件允许按实际情况**勾选**，不强迫所有项目都声称完成了全部流程。

---

## 一、开发环境（按实际勾选）

- [ ] 有本地 IDE / SDK，可本地编译
- [ ] 有本地 diff 工具，可逐行审阅
- [ ] 可跑 lint / 单元测试
- [ ] 走标准 PR 流程（fork → PR → review）
- [x] **仅靠云端 CI 编译（无本地工具链）** —— *（依赖 GitHub Actions + JDK 8 + Gradle 5.6.4）*
- [x] **仅靠移动端 / 手表端开发** —— *（主要使用手表端的 MGit 及手机端的 Pydroid 3 编写与运行 Python 修复脚本）*
- [x] **走直推 master（无 PR 流程）** —— *（发生过强制推送覆盖代码的惨案，后通过网页端恢复）*

> 未勾选的条目，代表**本仓库物理上无法执行**，不是"忽略了"。

## 二、我们实际执行的机制（做了什么就勾什么）

- [ ] **未测试**（见下方诚实声明）

> 未勾选的条目，代表**本仓库没有条件做**，不是"忘了做"。

## 三、诚实声明

**以下情况如实标注，不得美化：**

- **关于真机测试**：本仓库的核心 UI 与传输功能已在数台老旧安卓设备（包括智能手表）上通过真机验证。但受限于物理设备数量，部分冷门 API 或特定 ROM 的边缘场景尚未覆盖。
- **关于云端编译**：CI 编译通过仅代表语法与依赖正确，不代表所有功能在您的特定设备上绝对可用。
- **关于 AI 生成**：本项目属于极端的 AI 辅助驱动开发，大量核心协议（如手写 HTTP 栈、STUN 探测、UPnP 穿透）由 LLM 生成，并通过 Python 脚本进行外科手术式打补丁。请在使用前自行评估风险。

## 四、敏感模块清单（按实际填写）

以下模块涉及安全、权限、数据销毁等高危操作。请按**实际验证状态**标注：

| 模块 | 验证状态 |
|---|---|
| `CrossNetActivity.java`（跨网 ntfy.sh 中转与 IPv6 直连） | ✅ 真机测试（同设备自连及跨网请求解析已通过） |
| `StunClient.java`（手写 UDP STUN 探测） | ⚠️ 仅 CI 编译 / 部分真机测试（受限于公网环境） |

| `HttpServer.java` / `Router.java`（手写网络底层） | ✅ 真机测试（局域网内多设备收发正常） |
| `PrepareUploadHandler.java`（PIN 码鉴权与拦截） | ✅ 真机测试 |
| `WebShareHandler.java`（Web 端并发上传及路径沙箱） | ✅ 真机测试（浏览器互传及多文件切片正常） |

> 标注 `⚠️ 仅 CI` 或 `❌ 未验证` 的模块，**不代表不能发布**，但使用前请评估风险。

## 五、我们承认这不完美

形式化的 PR 流程、逐行代码审阅、本地静态分析，这些在本仓库里**可能全部缺位**。

我们用「**披露 + 门禁（CI） + 默认关**」承担了**实质责任**，而不是假装做到了所有**形式责任**。

这是约束下的选择，不是对标准的否定。

---

## 六、给其他极限约束开发者的建议

如果你也在极端约束下开发（无本地工具链 / 移动端 / 手表端），这套最小责任清单供参考：

1. **诚实披露 AI 参与度**（不要美化比例）
2. **高危功能默认关闭**（代码层面）
3. **能做的门禁不绕过**（有 CI 就卡 CI，没有就靠人工）
4. **测试状态如实标注**（做了就勾，没做就写"未测试"）
5. **敏感模块清单公开**（让外部能核对你测过什么）

**五件事做到了，你就已经承担了人类责任。** 形式上像不像别人，不重要。该勾选的就勾选。
