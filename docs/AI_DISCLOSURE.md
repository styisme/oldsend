# AI 生成说明

本项目（OldSend）在开发过程中大量使用了大型语言模型（LLM）辅助生成代码与文档。

## 核心声明
本项目采用**“人类主导需求与验收，AI 辅助生成与修补”**的协作模式。所有由 AI 生成的代码在合入主分支前，均需通过 CI 编译门禁，并在真实物理设备上进行核心功能的冒烟测试。人类开发者对最终发布的代码质量承担全部责任。

## AI 参与的部分
- **架构设计**：分层结构、跨网穿透逻辑、STUN/UPnP 协议手写。
- **业务逻辑**：文件并发、断点续传、黑白名单路由分发、剪贴板同步。
- **UI 代码**：Web SPA 网页开发、自定义 MD3 Switch、深色模式递归遍历。
- **文档与脚本**：README、CI 构建脚本、以及用于修复项目的一键 Python 补丁。
- **本次 v2.0.1 修复**：组播扫描逻辑补充（MulticastLock）、网页端路由补全、深色模式背景兜底渲染、多语言词条补全。

## 人类参与的部分
- **需求定义**：提出“既要局域网，又要跨网穿透”、“单文件变多选”等极端需求。
- **功能验收**：在古早 Android 设备上真机测试，把报错日志砸给 AI 修复。
- **Bug 定位**：解决诸如 `git push -f` 导致代码丢失、变量未加 final、少 import 等物理/语法事故。
- **安全兜底**：校验签名流程、GitHub Secrets 配置、以及敏感权限（如读写存储、网络组播）的合理性。

## 风险提示
由于大量代码为 AI 生成：
- 边缘情况处理可能不完整（如特殊路由器下的 UPnP 失败）。
- 在某些极度特殊的定制 ROM 上，UI 布局可能依然存在溢出。
- 跨网功能（如 ntfy.sh 中转、STUN 探测）受限于第三方服务与公网环境，稳定性不保证。

## 测试与验证边界
- **已验证**：核心局域网收发、Web 端多文件上传、深色模式切换、基础多语言渲染。
- **未全面验证**：极端弱网环境下的断点续传稳定性、非标准 NAT 环境下的 P2P 直连成功率。
